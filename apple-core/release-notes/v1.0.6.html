Apple Core 1.0.6

Apple Core 1.0.6 makes macOS privacy prompts work from both the menu bar and Settings on a Mac with no existing grants.

Fixes

  • Apple Core now becomes a regular foreground app and waits for macOS to confirm that it is active before requesting access. Earlier builds called the permission API immediately after asking to become active, and Tahoe could deny that request without displaying a prompt.
  • Calendar, Contacts, and Reminders now check the result of the permission request. A denied request can no longer leave the service checked and available to the MCP server.
  • Mail and Notes now request their Automation grants when you enable the service. Messages requests Automation before guiding you through access to chat.db.
  • Capture requests Camera, Microphone, and Screen Recording access even if one of the other grants is denied.
  • The menu bar and Settings now update the server only after activation finishes. If macOS denies access, the switch returns to off and the server keeps the service unavailable.

Permission coverage

Calendar, Contacts, Location, and Reminders use their native macOS permission prompts. Maps uses the Location grant. Mail and Notes use Automation, while Messages uses Automation plus the existing database picker. Capture uses Camera, Microphone, and Screen Recording.

Shortcuts and Utilities do not need a macOS privacy grant, so they enable without a permission prompt.

Upgrading

1.0.3 and later update automatically. Installs on 1.0.0 through 1.0.2 still need the one-time manual reinstall described in the 1.0.3 notes, because their update signing key no longer matches the feed.
