Apple Core 1.0.4

Apple Core 1.0.4 fixes remote OAuth discovery and stops service toggles from failing silently.

Fixes

  • Cloud connectors can complete OAuth: the OAuth issuer and the allowed-origin list are now both derived from the tunnel hostname. A server first configured without a hostname kept a localhost-only origin list and went on advertising an issuer of http://localhost:8756 through the public tunnel, so any cloud client that read the discovery documents was sent to the user's own machine and could never finish the flow. A config written before the hostname existed now repairs itself at launch instead of only when the Cloudflare pane is opened.
  • Service toggles explain themselves: a toggle that could not be enabled reverted with no message, which was indistinguishable from a broken control. The row now shows what macOS refused.
  • Refused permission prompts are named as such: macOS reports a plain "denied" both when you click Don't Allow and when it declines to show a prompt at all. The second case is the normal one on a Mac reached over Screen Sharing, where another process holds the foreground, tccd logs "Policy disallows prompt", and nothing is written to the privacy database — so no service can ever be granted there. Apple Core now distinguishes the two and says which happened.

Upgrading

1.0.3 and later update automatically. Installs on 1.0.0 through 1.0.2 still need the one-time manual reinstall described in the 1.0.3 notes, because their update signing key no longer matches the feed.
