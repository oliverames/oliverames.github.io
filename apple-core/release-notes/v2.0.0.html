Apple Core 2.0

Apple Core is now free for local access. No license key or activation is needed.
Existing local tokens, service permissions, shared folders, and approved clients
continue to work.

See what clients are doing

The menu shows connected clients and commands running now, described in plain
English. Recent activity shows whether a command completed or failed. Activity
stays in memory and does not store command arguments or results. Service switches
are in Settings, with a single Pause Apple Core action in the menu.

Use two Macs independently

Each Mac has its own hosted invitation and Connection ID. When settings arrive
through Migration Assistant or a restored backup, Apple Core identifies the
original Mac and offers a separate connection. It never silently takes over the
other Mac's hosted access. The invitation field has a full-width layout in
Settings and setup.

Hosted access replaces self-hosted tunnels

Remote access uses Apple Core hosting at mcp.applecore.app. Open Settings,
choose Access, select Anywhere, and enter a hosting invitation. The Mac must
remain running and connected.

This update stops the old Apple Core Cloudflare background agent and removes
its plist only after confirming the agent is unloaded. If cleanup fails, the
plist stays for retry at the next launch. The retired Cloudflare API token is
removed from Keychain. The cloudflared program, remote tunnel, and DNS record
remain until you remove them. Clients using the old tunnel address need to be
connected again through Apple Core hosting.

Hosting remains available by invitation. A USD 4.99 monthly hosted subscription
is planned through RevenueCat, but production checkout is not enabled in this
release. Local access is free on each Mac.

A more familiar Mac app

Settings now use native app icons for services. Shared folders support dragging
folders in, revealing them in Finder, changing write access, and removing them.
General settings expose Dock and background preferences. Window size, sidebar
width, and the last settings pane are remembered. Token rotation asks for
confirmation, and connection approval defaults to Deny.

Updates on applecore.app

Signed updates and notarized downloads are hosted on applecore.app. This release
removes the old purchase header and enables normal Sparkle update checks. Builds
1.0.0 through 1.0.2 require a manual reinstall because their old signing key does
not match the current feed.
